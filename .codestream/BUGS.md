# Bugs

Defects in the product. One entry each, `BUG-001` upward.

**Log a bug when you find it by using the app.** That is the point of this file.
A bug found by reading a document is worth logging too, but a log that only ever
grows from document-reading is a log of the paperwork, not of the product.

**Write the entry so the next reader doesn't have to re-derive anything.** What
you did, what happened, what you expected. Concrete numbers beat adjectives.

Statuses: `OPEN` → `DIAGNOSING` → `IN_PLANNING` → `IN_EXECUTION` → `CLOSED`.
Use `WONTFIX` and say why rather than leaving something to rot in `OPEN`.

- **Cause, if known:** <wrong code / wrong spec / wrong idea — rule 6>
- **Fix goes to:** <the code / a spec correction / back to the goal>
